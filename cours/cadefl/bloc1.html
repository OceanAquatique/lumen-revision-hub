01 — La carte mentale du Bloc 1

Avant de cartographier un SI, il faut comprendre ce qu'on cartographie. Le cours commence donc par l'information, les ressources du SI et la distinction fondamentale entre SI et IT.

Le SI dépasse la technologie

Infrastructure + données + logiciels/procédures + personnes.

Le SI transforme l'information

Collecter, stocker, traiter et diffuser.

Cartographier = changer de vue

Flux de données, processus, couches métier/applicatives/technologiques.

Parcours CADEFL : cinq blocs, un même cas MedLink, un dossier cumulatif et une défense CODIR. L'évaluation annoncée est 60 % projet + 40 % pour les cinq quiz (5 × 8 %).

03 — Le système d'information, réellement

Infrastructure

Ordinateurs, imprimantes, serveurs, réseaux.

Data

Chiffres, lettres, images, sons ; structurés ou non.

Software & Procedures

Programmes et étapes prédéfinies suivies par les personnes.

People

Personnes qui alimentent, utilisent ou maintiennent le système.

Les quatre fonctions

Collect

Recueillir/saisir les données.

Store

Conserver le volume nécessaire de façon sûre.

Process

Transformer les données en information pertinente.

Diffuse

Mettre l'information à disposition de la bonne personne.

IS ≠ IT : dans le cours, IT = infrastructure + software. Le SI englobe l'IT mais aussi les données, procédures et personnes. Une carte purement technique est donc incomplète.

Opérationnel vs management

Operational Module

Opérations quotidiennes, court terme, coordination et optimisation du processus.

Management Module

Planification long terme, visualisation, décision et contrôle.

04 — DFD : voir la donnée circuler

Le livrable D1 mentionné dans le quiz demande un DFD Level 0. Un DFD met l'accent sur les échanges et transformations de données plutôt que sur la chronologie détaillée d'un processus.

External Entity

Source/destination extérieure au périmètre. Le quiz retient le carré.

Process

Traitement qui transforme des données.

Data Flow

Information qui circule entre les éléments.

Data Store

Stockage logique utilisé par le processus.

Méthode de lecture/construction

Définir le périmètre → identifier les acteurs externes → repérer les traitements → repérer les stockages → nommer les flux → vérifier que chaque donnée a une origine et une destination compréhensibles.

À ne pas confondre : un DFD n'est pas une topologie réseau. VLAN, ports, VM ou câblage ne constituent pas son objectif principal.

MedLink — éléments explicitement testés : les external entities de l'exemple sont Member et Healthcare Provider ; le data store D2 est le Member Registry.

05 — BPMN : voir le processus se dérouler

BPMN répond à la question : qui réalise quelle activité, dans quel ordre, avec quelles décisions et quelles communications ?

Events

Début, événements intermédiaires, fin.

Activities

Travail réalisé pendant le processus.

Gateways

Points de divergence ou de convergence.

Pools, lanes et flux

Un pool représente un participant à une collaboration ; les lanes structurent les responsabilités à l'intérieur. Le sequence flow décrit l'ordre des étapes d'un processus ; le message flow sert à représenter une communication entre participants.

Gateways à savoir distinguer

XOR / Exclusive

Une alternative est sélectionnée selon une condition.

AND / Parallel

Branches exécutables en parallèle et synchronisables.

OR / Inclusive

Une ou plusieurs branches peuvent être activées.

MedLink : le quiz donne le nom exact du pool cloud : MedLink Claims Service (Cloud). Le briefing demande aussi de montrer explicitement la legacy/cloud seam.
Exemple EPITA + approfondissement pédagogique

06 — ArchiMate & layer map

L'exemple pédagogique relie trois niveaux : le Business (processus métier), l'Application (systèmes qui les soutiennent) et la Technology (infrastructure sous-jacente).

Business

Acteurs, rôles, processus et services métier.

Application

Applications et services applicatifs qui soutiennent le métier.

Technology

Infrastructure sur laquelle les applications reposent.

Idée centrale : une layer map utile ne juxtapose pas trois inventaires. Elle rend visible la traçabilité : processus métier → application → infrastructure.

08 — MedLink : ce qui sert au Bloc 1

Fil rouge : MedLink n'est pas « le Bloc 1 ». Le dossier est la source de contexte commune aux cinq blocs. On ne retient ici que ce qui aide à lire et représenter le SI.

MedLink Europe est un assureur santé paneuropéen né en janvier 2024 de la fusion d'InsureNat, côté legacy/mainframe, et de CareFlow, côté cloud-native. Cette coexistence explique l'importance de rendre visible la frontière legacy/cloud.

Claims Journey

Le Healthcare Provider soumet le claim via le Provider Portal ou sur papier, puis une saisie opérateur rejoint le même Claims API. Le Claims API publie claim.created ; plusieurs services cloud y souscrivent. Une approbation automatique peut rester côté cloud. Sinon, le claim est transmis au Legacy Core, rejoint le batch nocturne, est validé contre le Member Registry et peut être routé vers un claims adjuster.
