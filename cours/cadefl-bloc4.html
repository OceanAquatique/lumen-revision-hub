Support CADEFL · Bloc 4

01 — La mission : passer du plausible au défendable

Le Bloc 4 change de nature : tu ne pars plus d’un diagramme déjà structuré. Tu pars d’une vidéo longue et imparfaitement structurée et tu dois reconstruire une représentation du SI avec l’aide de l’IA — tout en conservant la capacité de démontrer d’où vient chaque affirmation.

Règle absolue : NO EVIDENCE = NO FACT. L’IA peut extraire, structurer, comparer et reformuler. Elle ne doit pas remplir les blancs. Une réponse UNKNOWN correctement justifiée vaut mieux qu’une information plausible inventée.
Source

Une vidéo longue choisie par l’équipe.

Outil

IA générative autorisée et attendue.

Temps

Session autonome de 3 heures.

Équipe

Travail annoncé en groupe de 3–4 étudiants.

Le point important n’est pas seulement le résultat final. Chaque flèche est une frontière de contrôle. Tu dois pouvoir répondre : quel passage vidéo justifie cette ligne ? quel prompt a produit cette extraction ? pourquoi cette relation est-elle sur la carte ? pourquoi ce gap existe-t-il ?

Lecture GRC : on construit une chaîne de traçabilité. La qualité n’est donc pas « la carte a l’air vraie », mais « la carte est explicable, reproductible et auditable à partir de la source ».

Phase 1 · Video Investigation

03 — Exploiter une masse d’information sans tout regarder linéairement

La compétence testée n’est pas « regarder 40 minutes de vidéo ». Elle consiste à utiliser intelligemment les outils pour exploiter une source non structurée sans perdre la provenance de l’information.

Transcript existant

Utiliser sous-titres/captions lorsque disponibles.

Transcription

Générer un transcript si nécessaire, puis conserver ses limites.

Recherche ciblée

Rechercher passages, mots-clés et timestamps plutôt que parcourir aveuglément.

Le Method Log

Pour chaque outil ou méthode, note quatre choses : Tool used · Method · What worked · Limitations. C’est une preuve de méthode et pas seulement une liste d’outils.

Piège : nettoyer un transcript ne donne pas le droit de « corriger » silencieusement un nom propre incertain. Une erreur ASR doit rester visible comme incertitude tant qu’elle n’est pas vérifiée.
Phase 2 · Prompt Engineering

04 — V1 → V2 : le prompt comme dispositif de contrôle

Le professeur ne cherche pas simplement « le meilleur prompt ». Une V1 imparfaite suivie d’une analyse lucide et d’une V2 précise démontre mieux la compétence attendue qu’un prompt final sans historique.

DimensionQuestionCe qu’une V2 robuste doit faire
ScopeQue cherches-tu ?Fermer le périmètre : types d’éléments, paysage visé, exclusions.
EvidenceD’où vient chaque claim ?Exiger citation/paraphrase, identifiant de passage et/ou timestamp.
UncertaintyQue faire quand l’info manque ?Autoriser explicitement UNKNOWN et les niveaux de confiance.
StructureQuel format de sortie ?Imposer colonnes et format exploitables.
HallucinationQu’est-il interdit d’inférer ?Interdire technologies, owners ou relations non présents dans la source.

Prompt Defense : six questions

1 · Objective

Qu’essayais-tu d’obtenir ?

2 · Prompt Design

Pourquoi ce rôle, ce contexte, ces contraintes ?

3 · Result

Qu’a produit l’IA et était-ce utile ?

4 · Problem

Qu’était-il ambigu, générique ou non supporté ?

5 · Improvement

Comment V2 corrige-t-elle précisément V1 ?

6 · Evidence

Quel exemple concret démontre l’amélioration ?

À retenir : « J’ai demandé à l’IA d’améliorer mon prompt » n’est pas une justification. Tu es évaluée sur ta capacité à CONTROL · CHALLENGE · IMPROVE le résultat.
Phase 3 · Evidence Extraction

05 — Evidence Table : transformer le transcript en faits traçables

Les types à rechercher sont explicitement donnés : Actors, Processes, Applications, Data, Technology, External systems, Flows, Owners, Dependencies.

IDTypeElementRelationshipEvidenceTimestampConfidence
E01Actor……Citation / paraphrase12:43High
E02OwnerUNKNOWN—No evidence—Unknown
UNKNOWN IS A VALID ANSWER. Inventer un owner est plus grave que laisser Owner = UNKNOWN. Le manque d’information devient lui-même une information utile pour l’investigation suivante.

Evidence ≠ plausibilité

Une technologie peut être courante dans ce type d’environnement et rester interdite dans la carte si la source ne la mentionne pas. De même, voir le mot « PostgreSQL » ne prouve pas que PostgreSQL est la base de production : la preuve doit supporter l’affirmation exacte.

Phase 4 · Attack Your Own AI

06 — AI Error Log : séparer production et contrôle

Le Bloc 4 impose un second passage : demander à l’IA de critiquer sa propre extraction, avec un prompt de critique construit par l’équipe.

VERIFIED

La source prouve précisément le claim.

UNCERTAIN

La source est partielle, vague, ambiguë ou endommagée.

UNSUPPORTED

Aucun passage ne supporte le claim.

AI claimSource evidenceVerdictAction
Claims API existsPassage identifiéVERIFIEDKeep
Kafka is usedNoneUNSUPPORTEDRemove
CIO owns applicationNoneUNCERTAIN / UnknownInvestigate
Compétence professionnelle : utiliser l’IA pour produire, puis utiliser un second passage pour contrôler la production. Le rôle du deuxième prompt n’est pas de « rendre le texte meilleur », mais de tester la solidité des claims.

Les systèmes externes sont placés autour du paysage lorsqu’ils sont pertinents. L’objectif est une cartographie simplifiée et executive-friendly, construite à partir des preuves validées — pas une encyclopédie graphique.

Règle de construction : une box ou une relation non soutenue par l’Evidence Table doit être supprimée, marquée comme incertaine ou transformée en gap. La carte ne doit pas « lisser » les inconnues.
Phase 5 · Coverage Matrix

08 — Coverage Matrix : croiser les représentations

Pour chaque élément, le support demande de vérifier sa présence dans plusieurs vues : Video/source · Process · Architecture · Asset register.

Coverage check, not compliance audit. Une case absente est une piste à investiguer, pas un verdict de faute ou de non-conformité.
Phase 6 · Gap Analysis

09 — Gap Register : quatre catégories seulement

Undocumented Flow

Interaction visible dans une source mais absente de la cartographie.

Unclear Ownership

Le composant existe mais son owner n’est pas établi.

Orphan Element

Un élément apparaît mais n’est relié au reste nulle part.

Inconsistent Naming

Plusieurs noms semblent désigner le même objet.

GapEvidenceCategoryConfidenceRecommended action
G01…Undocumented flowHighValidate flow
G02…OwnershipHighIdentify owner
A GAP IS A QUESTION REQUIRING INVESTIGATION — NOT AUTOMATICALLY A FAILURE. C’est une nuance essentielle : le registre sert à organiser l’incertitude et la prochaine action.
Phase 7 · Executive Cartography Brief

10 — « You have 10 minutes before the CIO meeting »

Le dernier exercice impose un changement d’audience. À partir du travail validé, l’IA doit produire un brief de 150 mots maximum, et le prompt utilisé doit être remis avec le résultat.

1

What do we understand about the IS?

2

What doesn’t align?

3

What remains unknown?

4

What should we investigate next?

Le danger final : la synthèse peut réintroduire des hallucinations supprimées plus tôt. Un bon prompt de brief doit donc restreindre son input aux tables validées et interdire tout nouveau fait.
Cas d’application étudiant · Waltz · non officiel

11 — Votre rendu Waltz : ce qu’il démontre particulièrement bien

Votre équipe a choisi l’option Waltz / Deutsche Bank et a construit un rendu qui applique la méthode du Bloc 4. Cette section sert d’exemple de raisonnement, pas de correction officielle.

1 · Un choix de scope très pertinent

Vous avez détecté que la vidéo mélange le SI réel autour de Waltz chez Deutsche Bank et des données de démonstration. Votre convention REAL / SAMPLE empêche FoxTerrier ou « CIO Office » d’être transformés en composants/owners réels de la banque.

2 · V1 volontairement observable → V2 contrôlée

Défaut V1Correction V2
FoxTerrier pris pour une vraie application DBLayer REAL / SAMPLE obligatoire
Owner « CIO Office » inventéUNKNOWN si aucune preuve
Finance ERP inventé comme source des coûtsFlow prouvé, source system = UNKNOWN
Kafka / REST / Kubernetes ajoutésInterdiction de nommer une technologie absente du transcript
Sortie libreTable structurée avec IDs, evidence, §/timestamp et confiance

3 · Une convention de preuve exploitable

Le transcript est découpé en 22 paragraphes §P01–§P22. Les timestamps sont annoncés comme approximatifs (±1 min), tandis que l’identifiant de paragraphe constitue la référence exacte. Cette distinction est propre : elle ne fait pas passer une estimation pour une mesure exacte.

4 · L’audit corrige réellement l’IA

Votre Error Log ne se contente pas de valider la première extraction. Exemples : Kafka est supprimé faute de preuve ; PostgreSQL passe à UNCERTAIN car la vidéo prouve qu’il est supporté, pas utilisé en production ; les APIs sont reformulées comme internes avec consommateurs UNKNOWN.

5 · La System Map conserve les inconnues

La carte en quatre couches reprend Business → Application → Data → Technology, ajoute les externes, référence les Evidence IDs et utilise le pointillé lorsque source, target ou owner reste inconnu. C’est exactement la bonne philosophie : visualiser l’incertitude au lieu de la masquer.

6 · Les gaps débouchent sur des actions

Votre Gap Register ne s’arrête pas à « il manque quelque chose » : chaque gap possède evidence, catégorie, confiance et action recommandée. Exemple : les coûts sont importés d’« other systems » mais la source, le format et la fréquence sont inconnus → identifier le système source et valider le feed.

Ce que je conserverais absolument dans le rendu : REAL/SAMPLE, UNKNOWN explicites, paragraph IDs, distinction timestamp estimé/référence exacte, et le principe « le mot apparaît dans le transcript ≠ le claim est prouvé ». Ce sont les éléments qui donnent au travail sa vraie maturité méthodologique.
Point à vérifier avant dépôt : la fiche de cours annonce des équipes de 3–4 étudiants, alors que la couverture de votre rendu liste 5 personnes. Si le professeur a explicitement validé votre groupe de 5, aucun problème ; sinon c’est le seul point administratif que je vérifierais avant remise.
Révision active

12 — Flashcards

Principe absolu du Bloc 4 ?

NO EVIDENCE = NO FACT.

Chaîne d’investigation ?

Video → Transcript → Prompt → Evidence → Mapping → Gaps → Executive Brief.

Pourquoi conserver V1 ?

Parce que l’évaluation porte aussi sur la capacité à observer un résultat insuffisant puis améliorer l’instruction.

Les 5 dimensions du prompt ?

Scope · Evidence · Uncertainty · Structure · Hallucination.

UNKNOWN signifie échec ?

Non. C’est une réponse valide quand la source ne permet pas d’établir le fait.

Types recherchés dans l’Evidence Table ?

Actors · Processes · Applications · Data · Technology · External systems · Flows · Owners · Dependencies.

Les 3 verdicts de l’AI Error Log ?

VERIFIED · UNCERTAIN · UNSUPPORTED.

Structure de la System Map ?

Business → Application → Data → Technology, plus systèmes externes pertinents.

Coverage Matrix = audit de conformité ?

Non. Elle cherche les écarts de couverture à investiguer.

Les 4 catégories de gaps ?

Undocumented Flow · Unclear Ownership · Orphan Element · Inconsistent Naming.

Un gap est-il une faute ?

Non : c’est une question nécessitant investigation.

Les 4 questions du CIO Brief ?

What do we understand? What doesn’t align? What remains unknown? What should we investigate next?

Limite du CIO Brief ?

150 mots maximum + remise du prompt utilisé.

Dans Waltz, pourquoi PostgreSQL = UNCERTAIN ?

La source prouve que Waltz supporte PostgreSQL, SQL Server et MariaDB, pas que PostgreSQL est la DB de production.

Pourquoi REAL / SAMPLE est important dans votre rendu ?

Pour ne pas confondre le paysage réel de Deutsche Bank avec les données fictives utilisées dans la démonstration du produit.

Pourquoi un second prompt de critique ?

Pour séparer la production de l’IA de son contrôle et vérifier chaque claim contre la source.

Bloc 4 · Key Takeaways

14 — Mémo express

Méthode

  • V1 → observer → corriger → V2.
  • Scope · Evidence · Uncertainty · Structure · Hallucination.
  • UNKNOWN est une réponse professionnelle.
  • Une preuve doit supporter le claim exact.
  • Produire puis auditer dans un second passage.
